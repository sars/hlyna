# Оформлення замовлення по-українськи — дослідження (24.10.2026)

«Неперевірено» = сторінка не відкрилась (403 / SPA) або лише вторинне джерело.

## 1. Поля і порядок
Норми: Horoshop (найпоширеніша платформа) — телефон перший, email необов'язковий, одна сторінка, вкладка «Швидке замовлення» (телефон, решту менеджер по телефону). Rozetka — ПІБ + телефон + відділення. Crafta.ua (відгуки 2023–24) втрачала замовлення через обов'язковий email; нині редіректить на shafa.ua. Visa Ukraine Checkout Friction Report (02.2026, 679 покупців): 73 % кидали покупку, 89 % купують з телефону, 43 % ненавидять повторне введення картки. Baymard: 14 % кидають, коли телефон обов'язковий без пояснення.

Рекомендована форма (одна сторінка, лише гість, телефон перший, мобільна):
1. Телефон (+380, зберігати E.164; «сюди надішлемо номер ТТН»).
2. Ім'я та прізвище (одне поле; ТТН НП потребує обидва).
3. Доставка (radio): Нова пошта відділення / поштомат → місто → відділення; Кур'єр НП → вулиця, будинок, кв.; Укрпошта (якщо студія вмикає); Самовивіз з майстерні (адреса з профілю). Ціна біля кожної опції («За тарифами перевізника», фіксована або «безкоштовно від N грн») — так моделює Horoshop.
4. Оплата (radio).
5. Коментар + чекбокс «Не телефонуйте, підтвердьте в месенджері» (Rozetka має статус «Оброблено автоматично»).
6. Email — лише коли в кошику сертифікат або онлайн-оплата.
7. Рядок згоди під кнопкою.
Кілька студій у кошику → по замовленню на студію, на одній сторінці блоками.

## 2. Доставка
- Нова пошта домінує. Типова конфігурація (модуль НП у Horoshop): відділення / поштомат з фільтром за типом (поштомат, ≤ 5 кг, ≤ 30 кг), кур'єр за адресою, платник, оголошена вартість і післяплата = вартість товару, «Контроль оплати» — за договором з NovaPay.
- API 2.0 (JSON POST з apiKey): Address.searchSettlements / getCities / getWarehouses / getStreet; Counterparty; InternetDocument.save (ServiceType, PayerType, CargoType, Weight, SeatsAmount, Cost, BackwardDeliveryData), getDocumentPrice, getDocumentDeliveryDate; TrackingDocument.getStatusDocuments. ТТН створює студія своїм ключем, не платформа. Зберігати на студію: apiKey, відправник, місто / відділення, типова вага, платник.
- Тарифи з 13.04.2026: ≤ 2 кг 90 грн, ≤ 10 кг 135, ≤ 30 кг 200 по Україні; оголошена вартість безкоштовно до 500 грн (0,5 % вище — неперевірено).
- Післяплата: покупець платить комісію NovaPay 2 % + 20 грн (1 % + 10 грн з карткою NovaPay з 01.06.2026). Продавець: «Договір післяплати», виплата того ж / наступного дня, 0,5 % на рахунок NovaPay, 1,3 % в інші банки; ФОП підключає в застосунку. «Сейф-сервіс» закрито 01.05.2025.
- Пакування (правила НП 1.6, 03.01.2025): кераміка — «крихке»: ≥ 3 шари плівки з бульбашками або ≥ 2 см амортизації, тришаровий гофрокартон, порожнини заповнені, маркування «Обережно, крихке» на двох найбільших сторонах. Дати студії вибір «лише відділення / кур'єр, не поштомат» для великих речей.
- Укрпошта: API через менеджера (PDF 2020). Meest: публічний довідник відділень, API за договором. Моделювати як значення перевізника з вільною адресою.

## 3. Оплата
Ставки (порівняння monobank на 01.09.2026): plata by mono 1,3 % UA / 2 % іноземні, LiqPay 1,3 % / 2 %, hutko (ПУМБ, ex-Fondy UA — неперевірено) 1,5 %, Portmone 1,5 %; Apple / Google Pay у mono, LiqPay, hutko; «схема маркетплейсу: лише plata by mono».

Split для маркетплейсу:
- **plata by mono**: задокументований split — `basketOrder[].splitReceiverId`, `agentFeePercent`; отримувачі через `GET /api/merchant/split-receiver/list`; підключення отримувачів — через підтримку. Найкращий варіант: UAH, ФОПи, mono-аудиторія.
- **LiqPay**: `split_rules` [{public_key, amount, commission_payer, server_url, rro_info}]; кожному отримувачу свій мерчант.
- **Fondy** split accounts з KYC — доступність для UAH не вказана (неперевірено). **WayForPay** — документів маркетплейсу не знайдено.
- Частинами: mono «Покупка частинами» (мерчант платить, напр. 2,9 % за 2 частини, до 24); ПриватБанк «Оплата частинами».
- Податки: лист ДПС 26.02.2026 №209/2 назвав «маркетплейс утримує комісію, платить нетто» негрошовим розрахунком для єдинника; Мінфін 27.04.2026 №11210-02-2/11660 — не порушення, якщо маркетплейс діє як субкомісіонер. Лишити можливість виставляти 10 % окремим рахунком, а не утримувати.

Зберігати вже зараз (провайдеро-незалежно): `payment_method`, `payment_provider`, `provider_payment_id`, `provider_payload jsonb`, суми в копійках, валюта 980, `platform_fee`, `seller_amount`, `fee_payer`, `payment_status` (unpaid, pending, hold, paid, partially_refunded, refunded, failed), журнал вебхуків (ідемпотентний за id події), профіль виплат студії (ФОП / ТОВ, IBAN, sub-merchant id, рахунок NovaPay), `fiscal_code` на рядок, `customer_email` nullable.

## 4. Юридичне й фіскальне
- ПРРО: позиція ДПС — інтернет-продавець фіскалізує карткові оплати й післяплату через перевізника, чек не пізніше передачі; чек може бути електронним. Верховний Суд 16.07.2025 (420/19624/24) став на бік продавця щодо післяплати NovaPay, позиція ДПС не змінилась. Повна передоплата на IBAN — без РРО. Фіскалізує продавець (студія); зберігати `fiscal_receipt_id/url` на замовлення, хук під Checkbox / Вчасно.Каса.
- Захист прав споживачів (ЗУ 1023-XII ст. 13): 14 днів від отримання на відмову; 90 днів, якщо підтвердження неповне; без відмови для товарів «виготовлення або переробки на замовлення споживача», що не продаються без втрат; доставка до 30 днів, якщо не домовлено інакше. Перелік КМУ №172 кераміки не містить. Позначати `made_to_order` на рядок і казати до покупки.
- Е-комерція ст. 11: замовлення через систему = акцепт; продавець невідкладно підтверджує; покупець отримує підтвердження з умовами повернення. Підтвердження має містити: номер, склад, ціни, доставку й оплату, назву й контакти продавця, умови повернення, посилання на оферту.
- Персональні дані (2297-VI): електронна згода «позначкою на сайті», має бути доказовою. Формула: «Оформлюючи замовлення, я погоджуюсь з публічною офертою та обробкою персональних даних для виконання замовлення» — зберігати час згоди і версію оферти. Законопроєкт 8153 — перше читання (неперевірено).
- Оферта: модель — bodo.ua (платформа продає послуги провайдерів: передані права, сертифікат не товар, 14 днів повернення). Для нас: платформа = інформаційний посередник і агент; договір купівлі студія ↔ покупець; студію називати в кожному підтвердженні.

## 5. Життєвий цикл
Орієнтири: Rozetka (Обробляється → Очікує оплати → Комплектується → Передано перевізнику → Доставляється → Виконано; скасування з причиною; реакція 2 / 24 год; дзвінок перед скасуванням), KeyCRM (Новий, Погодження, Виробництво, Доставка, Виконано, Відмінено), Horoshop (Нові, В обробці, Надіслане, Доставлене, Скасоване).
Пропозиція повна: new → confirmed → awaiting_payment → in_production → ready → shipped (ТТН) → delivered → completed (тут 10 %) | cancelled(reason) | return_requested → returned / refunded. Підтвердження — месенджер / SMS; дзвінок лише коли студія позначила «потрібне уточнення». (У v1 беремо 6 станів, див. PLAN.md.)

## 6. Сертифікати
Практика: KUST — на заняття і номінальні, електронні на email, друкований +50 грн, без терміну; «ЯР» — 3 місяці, папір або електронний; «Лев і Крук» на Rozetka — 6 місяців, без обміну; bodo — дата, +1 місяць автопродовження, обмін, без виведення в гроші, 14 днів повернення першому покупцю. Фіскально: погашення — «безготівкова / подарунковий сертифікат» у чеку; ДПС сперечається з єдинниками (неперевірено).
Модель: certificate {code, studio_id, type class | amount, nominal, recipient_name?, message, valid_until (12 міс., студія може 6), status issued | redeemed | expired | refunded, delivery email PDF | printed, redeemed_order_id}; погашення студією за кодом; одне продовження.
