# Кабінет студії — дизайн-рев’ю збудованих екранів

16.10.2026, дизайнер (варіант B, обраний 16.10). Звірено з макетами `01…20-*.png` і специфікацією `README.md` §4–7 на локальному сервері (база `hlyna_merge`, тестовий власник «Осоння»). Знімки — `.shots/kabinet-review/` (`d-*` 1280 px, `m-*` 390 px із дотиком, `v-*` перевірки), знімаються `node .shots/kabinet-review/review.mjs` (усі екрани й стани), `verify.mjs` (підпис, стан «Зберігаємо», індикатор перетягування), `extra.mjs` (стайлгайд 22–24, екран пароля зі службовим токеном). Після правок — ті самі команди дають знімки «після» під тими ж іменами. Відомі свідомі відхилення («Розділ 1 / 6», «6 / 10», «на перевірці від 14.10», заголовок студії «Осоння» з кікером) не рахую.

## Вердикт

**Приймаю з трьома обов’язковими правками у фото.** Побудовано за макетом: бланки на білому з 1px рамкою `ink-2`, фокус 2px кобальт, помилка 2px теракота з текстом під полем, підписи Golos 500 15px, підказки 13.5px — усі міри збігаються зі специфікацією (`measures.json`). Огляд, список студій, шапка й підвал кабінету, бар збереження в усіх семи станах (незбережене · чернетка · зберігаємо з кобальтовою рискою · збережено з «Далі: …» · помилка полів з посиланнями · мережа), примітка після збереження, переліки з «×», ціни з місяцем, чипи логотипа, чекбокси — відповідають макетам 03–10, 14–19 без зауважень по пропорціях. Перетягування фото працює мишею, довгим натисканням (380 мс, вібрація) і клавішами ← → / Home; свайп з плитки не переставляє; підпис зберігається при втраті фокусу (PATCH 200). Текст — як у README §5.

Це «гарно і зручно» на десктопі й у текстових розділах. На телефоні екран «Фото» — саме той, заради якого робили редизайн, — ще не зібраний: дії під плитками ламаються на два рядки, індикатор місця при перетягуванні не видно взагалі, а поле підпису відкривається за кадром. Після P1 можна показувати власнику; P2 — до публікації.

Примітки до того, що виглядає як помилка, але нею не є: «Зберігаємо…» на знімках `d-25…d-29` висіло, бо dev-сервер компілював маршрут PATCH (у `verify.mjs` запит іде 200 за < 1 с); у цін «Осоння» в базі `date_text` порожній, тому всі рядки кажуть «не вказувати», а огляд — «5 цін» без місяця (макет 05 припускав «жовтень 2026» — це я помилилась у даних, не код).

## P1 — виправити до показу власнику

### 1. Фото на телефоні: дії під плиткою переносяться на два рядки
- **Екран:** `/kabinet/studiya/…/foto` 390 px, `m-23-foto-added.png`, `m-10-foto.png`; те саме у стайлгайді `m-20-sg-kb-photos.png`.
- **Що не так:** при 3 колонках плитка 112 px, а «Головне · Підпис · Прибрати» в mono 10.5px потребують ≈ 150 px. Третя дія падає на другий рядок, ряди стають нерівними (у рядку 1 плитка «Головне» має один рядок дій, сусідні — два), сітка «пливе». Макет 13 цю проблему приховав, показавши на неголовних плитках лише дві дії — то була помилка макета, у специфікації §4.7 дій три.
- **Правка (CSS, `globals.css` блок PhotoManager):** на телефоні дві колонки, плитка ≈ 174 px, три дії вміщаються в рядок, фото видно, а палець має куди лягти при довгому натисканні:
  ```css
  .ui-pgrid { grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 12px; }
  @media (min-width: 40rem) { .ui-pgrid { grid-template-columns: repeat(4, minmax(0, 1fr)); gap: 14px; } }
  ```
  і прибрати перенос як запобіжник: `.ui-pt-a { flex-wrap: nowrap; gap: 0 9px; }`. Якщо колись дії знову не влізуть — нехай обрізається «Підпис», а не рветься рядок. README §4.7 і SYSTEM.md §4.4 («сітка 3 → 4 колонки») виправити на «2 → 4».
- **До:** `.shots/kabinet-review/m-23-foto-added.png` · **після:** той самий файл після `review.mjs`; орієнтир — плитки й підписи як у `docs/design/kabinet/20-desktop-editor-foto.png`, лише дві в ряд.

### 2. Індикатор місця при перетягуванні невидимий
- **Екран:** фото, обидві ширини, `d-27-foto-dragging.png`, `m-31-foto-touch-dragging.png`, збільшено `v-drop-indicator.png`.
- **Що не так:** `.ui-pt[data-drop='before'] .ui-pt-im { box-shadow: inset 4px 0 0 cobalt }` — внутрішня тінь малюється **під** вмістом елемента, а `<img>` займає всю плитку, тож кобальтової риски не видно ніколи (`verify.mjs`: `data-drop="before"` стоїть, тінь обчислена, але `elementFromPoint` на краю плитки повертає `IMG`). Власник тягне фото й не бачить, куди воно впаде; на телефоні, де привид 96 px закриває пів плитки, — тим паче.
- **Правка (CSS):** замінити тінь на псевдоелемент над картинкою:
  ```css
  .ui-pt-im::after { content: ''; position: absolute; inset: 0 auto 0 0; width: 0; background: var(--color-cobalt); pointer-events: none; }
  .ui-pt[data-drop='before'] .ui-pt-im::after { width: 4px; }
  .ui-pt[data-drop='after'] .ui-pt-im::after { left: auto; right: 0; width: 4px; }
  ```
  (у `.ui-pt-im` уже є `position: relative`). Плитку-ціль додатково не затемнювати — риски досить.
- **До:** `v-drop-indicator.png` (лівий край плитки 2 чистий) · **після:** той самий кадр із 4px кобальтовою рискою.

### 3. Поле підпису відкривається поза екраном і без фокуса
- **Екран:** фото, десктоп `d-24-foto-caption-open.png`, `d-25-foto-caption-saved.png` (підпис «Підпис до фото 2» зрізаний баром); телефон `m-24-foto-caption-open.png` (поле на 400 px нижче плитки, фокус лишився на кнопці «Підпис»).
- **Що не так:** після «Підпис» поле з’являється під сіткою, але нижче видимої частини (у `verify.mjs`: поле y = 914, бар y = 860 при висоті 900) і нічого не отримує фокус — на десктопі здається, що кнопка не спрацювала; на телефоні треба ще прокрутити й тапнути в поле. Специфікація §4.7 обіцяла «відкриває поле… збереження при втраті фокусу» — отже, поле має бути перед очима з курсором усередині.
- **Правка (`src/components/ui/PhotoManager.client.tsx`):** в ефекті на зміну `captionFor` — `input.focus({ preventScroll: true })` і `scrollIntoView({ block: 'center', behavior: reduced ? 'auto' : 'smooth' })`; у `.ui-pt-capf` додати `scroll-margin-bottom: 96px`, щоб липкий бар не накривав. Під плиткою, яку підписують, підсвітити дію: `button[aria-expanded=true] { color: var(--color-ink); text-decoration: underline; text-underline-offset: 3px }`. Enter уже зберігає — лишити; Escape — закрити поле (зараз лише блюр).
- **До:** `d-25-foto-caption-saved.png` · **після:** поле в центрі кадру з курсором, «Підпис» на плитці 2 підкреслено.

## P2 — варто до публікації

### 4. «Заповнено 5 з 6 розділів» ламається на два рядки
- **Екран:** `/kabinet` (`d-03-home.png`, `m-03-home.png`) — поруч довгий тег «на перевірці від 16.10»; бічна колонка редактора на десктопі (`d-04-overview.png` і всі `d-05…10`) — колонка 300 px.
- **Правка:** у `Meter` додати `short` → «5 з 6 розділів» і вживати його в `.ui-side` (так у макеті 19: «4 з 6 розділів»). У картці студії й в огляді на телефоні — `.ui-meter-v { flex-wrap: wrap }`, тег `margin-left: auto`: якщо не влазить, тег іде другим рядком праворуч, а заголовок лишається одним рядком. Тег скоротити до «на перевірці · 16.10» (`page.tsx` кабінету, рядок зі `StatusTag state="review"`).
- **До:** `d-03-home.png` · орієнтир: `docs/design/kabinet/19-desktop-editor-pro.png` (бічна колонка).

### 5. Подвійна лінійка під «Що правда про ваш посуд»
- **Екран:** «Для бізнесу», `m-08-biznes.png`, `d-17-biznes-filled.png`: 2px `ink` від `.ui-list-h` і одразу 1px `rule` від `.ui-checks` з 4px зазором.
- **Правка (CSS):** `.ui-list-h + .ui-checks { border-top: 0; margin-top: 0; }` — заголовок групи вже дає верхню лінійку.
- **До:** `d-17-biznes-filled.png` (y ≈ 613–620) · орієнтир `09-phone-biznes.png`.

### 6. Ціни: п’ять «не вказувати» без пояснення, що саме
- **Екран:** «Ціни», `m-07-tsiny.png`, `d-07-tsiny.png`. Коли дата порожня (у базі 1241 цін із 1515 без дати — це норма, не виняток), під кожним текстом стоїть самотній `select` «не вказувати»; що він про місяць, видно тільки з `aria-label`.
- **Правка:** видимий підпис колонки — на телефоні mono 11px `ink-2` верхній «Коли актуально» над `select` (`.ui-pr-d::before`, або справжній `<label>` 11px), на десктопі той самий текст один раз як заголовок колонки над першим рядком (у `.ui-list-h` праворуч: «5 цін … Коли актуально»). Порожній варіант назвати «місяць не вказано» (`ListEditor.client.tsx`, `<option value="">`). Новий рядок, як і зараз, одразу «жовтень 2026 (зараз)».
- **До:** `m-07-tsiny.png` · орієнтир `08-phone-tsiny.png`.

### 7. Липкий hover на дотику: після тапу кнопки-привиди лишаються чорними
- **Екран:** `m-12-saved.png` («Далі: послуги» чорна, хоч це `ghost`), `m-18-tsiny-new-row-bottom.png` («+ Додати ціну» чорна після тапу). На iOS/Android `:hover` тримається до наступного дотику — власник бачить «залипу» кнопку.
- **Правка (CSS, `globals.css` рядки `.ui-btn[data-variant='ghost']:hover`, `.ui-x:hover`, `.ui-pt-a button:hover`, `.ui-srow:hover`):** загорнути hover-правила в `@media (hover: hover)`; активний стан на дотику дати через `:active` (`background: paper-2`).

### 8. Зони дотику менші за 44 px
- **Де:** `ChoiceChip` — 34 px заввишки (`measures.json`: `cc.h = 34`), §4.2 обіцяв 44 через `::before`; дії під фото — 28 px без розширення; «Читати повністю» в `NowBlock` — 13 px (`p-0`); «Відновити · Відкинути» і «Спробувати ще раз» у барі — висота рядка.
- **Правка (CSS):** `.ui-cc input { inset: -5px 0 }` (невидимий `input` і є зоною дотику); `.ui-pt-a button { position: relative } .ui-pt-a button::before { content: ''; position: absolute; inset: -8px -4px }`; кнопкам у `.kb-note` і `.ui-savebar-s` — `padding-block: 8px; margin-block: -8px`.

### 9. На телефоні з фото зникає речення про згоду
- **Екран:** `m-23-foto-added.png`. Лід розділу («…Завантажуючи, ви дозволяєте показувати фото…») на телефоні схований (`hidden sm:block`), а підказка під кнопкою показується лише коли фото нема. У заповненому стані згоди не видно ніде.
- **Правка (`PhotoManager.client.tsx`, `picker('bottom')`):** під «Додати ще фото» завжди один рядок `.ui-pz-hint`: «JPG, PNG, HEIC · до 10 · завантажуючи, ви дозволяєте показувати їх на сайті з підписом студії».

### 10. Фокус-кільце після перетягування обводить порожнє місце
- **Екран:** `m-32-foto-after-touch-drag.png`, `d-29-foto-focus.png`: кільце 3px навколо всього `li`, разом із пустим низом (до правки 1 він ще й різний у сусідів).
- **Правка (CSS):** `.ui-pt:focus-visible { outline: 0 } .ui-pt:focus-visible .ui-pt-im { outline: 3px solid var(--color-cobalt); outline-offset: 3px }`.
